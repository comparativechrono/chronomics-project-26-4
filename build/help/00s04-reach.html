1. One against all

PLINK's --ld-snp fixes one variant and computes r² against every other within a window. --ld-window-kb sets how far to look, --ld-window-r2 0 says report everything rather than only strong pairs:

cd ~/project
plink2 --pfile scn5a --ld-snp 3:38651526:G:A \
       --r2-phased --ld-window-kb 300 --ld-window-r2 0 \
       --out scan_all
wc -l scan_all.vcor
sort -g -k7,7 -r scan_all.vcor | head -15

The last column is r². Sorting it largest-first shows the variants most tightly linked to rs41310749 across the whole region.

Check

Across all 2,504 people, no variant anywhere in the 500 kb reaches r² ≥ 0.8 with rs41310749. Nineteen reach 0.5, spanning 39.3 kb; thirty-five reach 0.2, spanning 52.5 kb. The highest r² in the file is with rs41310239 – the variant you already knew about.

2. The same scan, one population at a time

Reuse the superpop.txt you built in stage 2:

plink2 --pfile scn5a --ld-snp 3:38651526:G:A \
       --r2-phased --ld-window-kb 300 --ld-window-r2 0 \
       --pheno superpop.txt --loop-cats SUPERPOP --out scan
for f in scan.*.vcor; do
  n=$(awk 'NR>1 && $7>=0.8' $f | wc -l)
  echo "$f  variants with r2>=0.8: $n"
done
Check

In Europeans, 22 variants reach r² ≥ 0.8, and they span 50.6 kb – from 38,631,501 to 38,682,101. In Africans, essentially none do. The block the project is about is there, and it was hidden by pooling five continents into one sample.

Why pooling destroyed it

r² is a correlation, and a correlation computed across structured groups measures two things at once: whether the alleles travel together within a group, and whether the groups differ in frequency. Africans carry rs41310749 at 13% and almost none of the rest of the block; Europeans carry the whole block at 16%. Mixing them in one calculation lets the between-group difference swamp the within-group correlation.

This is the same statistical trap as Simpson's paradox, and it is why population genetics is done within populations and only then compared across them. Never compute LD in a pooled multi-ancestry sample unless you have thought hard about what the number will mean.

2b. Doing it yourself, and plotting it

You wrote an ld() function in stage 3. Apply it across every variant in the file and plot the result – this is the figure that makes the block visible.

library(ggplot2)
d <- read.table("~/project/scan.EUR.vcor", header = TRUE, comment.char = "")
names(d)[c(5, 7)] <- c("pos", "r2")
ggplot(d, aes(pos / 1e6, r2)) +
  geom_point(aes(colour = r2 >= 0.8), size = 1.1, alpha = 0.8) +
  geom_vline(xintercept = c(38.631501, 38.682101), linetype = 2, linewidth = 0.3) +
  scale_colour_manual(values = c("grey70", "#C5705D"), guide = "none") +
  labs(x = "position on chromosome 3 (Mb)", y = expression(r^2~"with rs41310749"),
       title = "Europeans") +
  theme_minimal(base_size = 11)
Check

A dense cluster of points near r² = 1 between the two dashed lines, and a scatter of low values either side. The cluster has edges: the r² does not trail off gently, it drops. That shape is what the word "block" means.

3. Where are the edges, and why there?

Blocks end where recombination has had a chance to cut. The genome has recombination hotspots – short stretches where crossing-over is tens of times more likely than average – and block boundaries tend to sit on them.

Think

Your block is 50.6 kb. The average human haplotype block is a few tens of kilobases, so this is ordinary in size. But its frequency is 16% in Europeans and 1.5% in Africans. Which of those two facts is the interesting one, and which is just how genomes are?

A boundary is not a fact

Every method of calling block boundaries gives slightly different answers, because r² is estimated from a finite sample and the threshold (0.8 here) is a choice, not a discovery. Quote your threshold whenever you quote a block size, and check that your conclusions do not change if you use 0.7 or 0.9. Do that now – it takes one line.
